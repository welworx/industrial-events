Curated YAML data for selected industrial events across metallurgy, mining, materials, and process-engineering domains. Event records prefer official event pages when available; discovery and organizer pages are tracked separately to support maintenance. Static site outputs are generated during deployment from the source YAML files.

**Best way to consume the data**: [open the reader-friendly event site](https://industrial-events.pages.dev/).

**Something wrong/missing?** Please open a GitHub issue with a short note and links. 

## Feeds

- [Reader-friendly event site](https://industrial-events.pages.dev/)
- [Subscribe to all events calendar](https://industrial-events.pages.dev/calendars/all.ics)

- [Machine-readable feed index](https://industrial-events.pages.dev/calendars/index.json)

Filter feeds are generated for series, categories, event types, countries, domains, and co-located groups.

## Data Layout

```text
events/<domain>/<series-slug>/
  metadata.yaml
  <series-slug>-<year>.yaml
```

Use `metadata.yaml` for stable series information. Put edition-specific websites, dates, venue details, deadlines, and sources in the event file.

## Contributing

Content PRs should usually update only YAML under `events/` or `sources/`. CI validates the data and builds the generated site.

New YAML files are checked for reachable links with `uv run industrial-events-check-yaml-links`. A weekly workflow checks links related to events from the previous calendar year onward and opens one issue for invalid links that need deeper review. The workflow can also be manually dispatched with `scope=all` for an initialization pass over historical event links.

- Automation workflow: [docs/automation.md](docs/automation.md)
- Source references: [docs/sources.md](docs/sources.md)
- Contribution details: [CONTRIBUTING.md](CONTRIBUTING.md)
